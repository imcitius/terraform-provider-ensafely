# Terraform provider for Ensafely

`packages/terraform-provider` is the Ensafely Terraform provider
(`terraform-provider-ensafely`, provider name `ensafely`), built on
[terraform-plugin-framework](https://developer.hashicorp.com/terraform/plugin/framework).
The agreed design is GitHub #110; this package skeleton is #113. It is a Go
module (`github.com/imcitius/terraform-provider-ensafely`) in the repository's
`go.work`, and does not import the cloud code: it talks to the tenant API
documented in [`docs/api/openapi.yaml`](../../docs/api/README.md).

**Status:** provider configuration, HTTP client, acceptance harness, the
`ensafely_check` resource and data source (#114, #115), project/group settings
resources (#119), `ensafely_connection` (#118),
`ensafely_escalation_policy` (#117), `ensafely_alert_channel` (#116), and the
`ensafely_check_defaults` and `ensafely_platform_regions` singletons with the
`ensafely_platform_regions_available` data source (#120): all v1 resources
and data sources. The release is prepared but not yet published (#121): the
public mirror `imcitius/terraform-provider-ensafely`, goreleaser with
GPG-signed checksums and the Terraform/OpenTofu Registry submissions need the
owner's accounts; see
[Terraform provider release](../../docs/operations/tfprovider-release.md).
The registry address is `imcitius/ensafely`. User docs live in
[docs/index.md](docs/index.md) (Registry layout, generated by tfplugindocs).

This directory is mirrored as the root of the public repository on
`tfprovider-v*` tags; development happens here, in the monorepo. Links to
`../../` paths only resolve in the monorepo.

## Configuration

| Argument | Environment | Default |
|---|---|---|
| `api_key` (sensitive) | `ENSAFELY_API_KEY` | none; required |
| `endpoint` | `ENSAFELY_ENDPOINT` | `https://app.ensafely.com` |

Applying needs a key with the `api_write` scope (owner decision on #109); an
`api_read` key only allows `GET`, which is enough for `terraform plan` and
`-generate-config-out`. Terraform 1.11 or newer is required for write-only
secrets. Onboarding (key, provider block, importing a Tenant) is the
[getting started guide](docs/guides/getting-started.md).

## Conventions for resources (T4–T10)

- Secrets: `<field>_wo` (`WriteOnly: true`, read from `req.Config`, because it
  is null in the plan) plus a plain `<field>_wo_version` number. Send the
  secret only on create or when the version changes. No `sensitive` fallback.
  `ensafely_writeonly_probe` in `internal/provider/writeonly_probe_test.go` is
  a test-only reference implementation.
- Name-keyed resources (alert channels, escalation policies): the name is the
  ID and has `RequiresReplace`.
- Inheritable fields are `Optional`, not `Computed`; null means "inherit".
  Only server-assigned values are `Computed`.
- Every resource implements import.
- Configure: `clientFromProviderData`. Errors: `addAPIError` keeps quota,
  plan, scope and rate-limit details. Read: `removeIfNotFound` drops a 404 from
  state.

## Checks

`ensafely_check` (`resource_check.go`) and the `ensafely_check` data source
(`data_source_check.go`) manage the http, tcp, icmp, dns, ssl_cert,
domain_expiry and passive types (#114) and pgsql_query, mysql_query, redis,
mongodb, ssh, smtp, grpc_health and websocket (#115). The replication and
time-query database variants are not managed. `databaseType` builds the two
query types, whose fields live in the nested `pgsql` / `mysql` API objects. One field table in `check_mapping.go`
(`commonCheckFields`, `checkTypes`) drives the resource schema, the data
source schema and both directions of the JSON mapping; add a type or field
there. `check_schema.go` builds the schemas and holds the validators.

- **Flat API, nested blocks.** The API payload is flat with a `type`
  discriminator; each type is a `SingleNestedBlock`. `ValidateConfig` requires
  exactly one block, and the block's required arguments (Terraform rejects
  `Required` inside an absent single nested block, so they are optional in the
  schema). A block plan modifier replaces the check when a block appears or
  disappears, i.e. on a type change.
- **Zero means unset.** The API omits zero values, so `""`, `[]` and `0` read
  back as null. Schemas therefore reject explicit empty values, integers start
  at 1, and booleans are `Optional+Computed` with a `false` default. Inheritable
  fields (`interval`, `severity`, `alert_channels`, `re_alert_interval`,
  `retry_count`, `retry_interval`, `escalation_policy`) are optional and not
  computed. `retry_count = 0` is not accepted until the API can tell it from
  unset.
- **Full PUT.** The API replaces editable fields on PUT, so update sends the
  whole configuration; omitted secrets are kept by the server.
- **Identity.** Create generates a v4 UUID, posts it with `client.Idempotent()`
  and, if the POST fails with a 5xx/409/transport error, adopts the check that
  exists under that UUID.
- **Secrets.** `http.basic_auth_password_wo`, `http.headers_wo` (all header
  values are secret, because the API masks them), `password_wo` of
  pgsql_query, mysql_query, redis and smtp, and `mongodb.uri_wo` (the API
  treats the whole URI as a secret) follow the write-only convention. A
  version change without a value clears the secret (`""` / `[]`). URLs with a
  password (`http.url`, `websocket.url`) are rejected, because the API masks
  it on read. SSH checks only read the banner and have no credentials.
- **Connections.** `connection_id` (UUID of an `ensafely_connection`) is
  accepted for http, pgsql_query, mysql_query and mongodb, the types the
  server hydrates from a Connection; other types reject it. Fields a
  Connection supplies (`host`, `http.url`, `mongodb.uri_wo`) are then not
  required, and inline credentials (`username`, `basic_auth_user`, credential
  `_wo` secrets) conflict with it. The API keeps a stored reference when
  `connection_id` is omitted, so the provider always sends it (`""` for none).
  While `connection_id` is set, credential secrets are sent as cleared, so no
  stale inline password remains; when a check leaves its Connection, they are
  sent again without a version bump. `http.headers_wo` is not a credential:
  the server merges Connection headers with the check's.
- **Unsupported types.** Read of a check with another API type is an error in
  the resource (clear message on import) and leaves every block null in the
  data source.

Acceptance tests (`resource_check_acc_test.go`): per type create → empty plan →
update → import → destroy; type change replaces; inherited fields stay null and
a check-defaults change is an empty plan; write-only secrets checked through the
API and the raw state for every secret-bearing type; `connection_id` round
trip (empty plan, import, switch to inline credentials and back, conflict
error); data source.

Server gaps that broke two of these tests (inherited `severity` read back as
`critical`; passive `timeout` dropped on read) were fixed by T2 (#112); the
suite now passes in full. Explicit `retry_count = 0` is still deferred
(see [docs/api/README.md](../../docs/api/README.md#error-behavior-and-t2-gaps)).

## Project and group settings

`resource_hierarchy_settings.go` implements `ensafely_project_settings` and
`ensafely_group_settings` using the same nullable API payload. Both expose
`enabled`, `duration` and `re_alert_interval` as optional, non-computed overrides.
The `project` and `group` keys require replacement when changed. Names must be
nonempty and contain no slash; each API path segment is escaped independently.

Create/update use PUT. Read uses the stored overrides, without resolving
defaults. Import IDs are `<project>` and `<project>/<group>`. An absent settings
row returns 200/null and remains managed. Destroy sends null for all three
overrides, restoring inheritance without deleting any project, group or Check.
Neither maintenance nor `updated_at` is stored in state, so UI maintenance
changes cause no drift. The API preserves maintenance on update and reset.

See the [project](docs/resources/project_settings.md) and
[group](docs/resources/group_settings.md) resource docs and examples.

The acceptance tests exercise both resources against the local app, set
maintenance through the UI's API, assert an empty plan, remove overrides on
update, verify import, and check that destroy resets overrides while preserving
the exact maintenance window. Unit tests cover null/false/empty-string mapping,
escaped paths, invalid imports and error handling.

## Connection

`resource_connection.go` implements `ensafely_connection` against
`/api/connections`. The `id` is the server-assigned UUID (the only computed
attribute); `name` and `type` update in place, as the API allows. `host`,
`port`, `username` and `params` are optional and sent on every PATCH, which
replaces them. `params` is a nested object with the documented non-secret keys
(`db_name`, `ssl_mode`, `replica_set`, `auth_source`, `base_url`); other keys
set outside Terraform are not stored in state and are preserved on update (the
provider reads the current params before PATCH).

Secrets follow the API's secret contract (`internal/secret`: password never
returned, header values and URL passwords masked as `****`; omitted keeps,
`""`/`{}` clears). Both are write-only pairs: `password_wo` +
`password_wo_version` and `headers_wo` (map) + `headers_wo_version`. Each
needs its version (`ValidateConfig`, which also rejects the literal `****`
and a password inside `base_url`). Create sends a set secret; Update sends it
only when its version changes, and clears it (`""` / `{}`) if it is null then.
Otherwise it is omitted and the API keeps it. A password-bearing `base_url`
set outside Terraform reads back masked; removing it from configuration sends
`""` (omission would keep it), and the resulting `""` reads as null.

Import takes the UUID; versions are not readable. Destroy treats 404 as done
and turns the 409 "in use" response into a diagnostic listing the referencing
Checks.

Tests: `resource_connection_test.go` drives CRUD against an in-memory API with
the server's masking/keep rules (payloads, rotation, clearing, unmodelled
params, masked base_url, 404/409/500, import ID validation).
`TestAccConnection` runs create → empty plan (secrets changed, same versions)
→ update (version bumps, rename) → empty plan → import, through a recording
reverse proxy to the app that proves which password and header were sent in
each request, and checks that no secret reaches state.

See the [resource doc](docs/resources/connection.md) and example.

## Escalation policy

`resource_escalation_policy.go` implements `ensafely_escalation_policy` against
`/api/escalation-policies`. Both `name` and the computed `id` identify the policy
by name; the API's numeric ID and timestamps are excluded from state. Changing
`name` requires replacement. `step` is a list of nested blocks with required
`channel` and `delay_min` attributes, so order and repeated channels survive
reads and writes. Validation requires a nonempty name/channel, at least one
step, and nonnegative integer delays, while deferring unknown values.

Create uses POST; Read uses GET by escaped name; Update uses PUT; Delete uses
DELETE and accepts 404. Import takes a name and reads its persisted steps.
Reorder/add/remove operations update in place. Delays are minutes from the
initial failure, not from the preceding step.

Unit regressions cover ordered JSON mapping, duplicate channels, escaped names,
import and API failures. `TestAccEscalationPolicy` checks create → empty plan →
reorder → add → remove → import → empty plan → destroy against the local app.
Each update must retain the numeric database ID; a rename must plan replacement.
See the [resource doc](docs/resources/escalation_policy.md) and
[example](examples/resources/ensafely_escalation_policy/resource.tf).

## Alert channel

`resource_alert_channel.go` implements `ensafely_alert_channel` against
`/api/alert-channels`. `name` is the ID (`RequiresReplace`; `ModifyPlan` keeps
`id` equal to the planned name). The type is one of five `SingleNestedBlock`s
(`email`, `telegram`, `slack`, `discord`, `webhook`; the block name is the API
type). One table, `channelTypes`, lists each block's plain fields and secrets
and drives the schema, validation and both directions of the mapping; its
secret keys must match the cloud's channel table (`internal/secret`).
Required fields (`email.to`, `telegram.chat_id`) are optional in the schema
and enforced by `ValidateConfig`, as for Checks. A block plan modifier replaces
the channel when a block appears or disappears (type change).

- **Secrets.** Every secret key is a write-only pair (`bot_token_wo`,
  `signing_secret_wo`, `webhook_url_wo`, `url_wo`, `secret_wo`, `headers_wo`
  map, each with `_wo_version`). Create sends set secrets; Update sends a
  secret only when its version changed, and clears it (`""` / `{}`) if it is
  null then. Otherwise it is omitted and the API keeps it. `****` and empty
  values are rejected.
- **Read.** `GET /api/alert-channels/:name` (T2). Empty strings and lists read
  as null; secrets are null and versions come from prior state. A type changed
  outside Terraform shows as the other block (plans a replacement); a type
  this provider does not manage is an error naming it.
- **Update** reads the current config first and sends the full block plus the
  keys the schema does not model (legacy SMTP settings), because the PUT
  replaces every non-secret key.
- **Delete** accepts 404; the default `Email` channel's 403 becomes a
  diagnostic pointing to `removed { lifecycle { destroy = false } }`.
- **Rename.** Checks reference channels by name, so a rename plans the
  channel's replacement and an in-place update of the referencing Checks'
  `alert_channels` in the same plan (Checks keep their UUID).

Tests: `resource_alert_channel_test.go` drives CRUD against an in-memory API
with the server's masking/keep/clear rules (per-type payloads and read-back,
import, rotation and clearing, unmodelled keys, drift, unsupported types,
conflict, default Email delete, validation). `resource_alert_channel_acc_test.go`
runs every type through create → empty plan (secret changed, same version) →
update (version bumps) → empty plan → import → destroy via the recording proxy,
checks API-stored values and that no secret reaches state; plus rename (channel
replaced, referencing Check updated in place) and type change (replace).
See the [resource doc](docs/resources/alert_channel.md) and
[example](examples/resources/ensafely_alert_channel/resource.tf).

## Check defaults and platform regions

Both are per-Tenant singletons with the ID and import ID `current`.

`resource_check_defaults.go` implements `ensafely_check_defaults` against
`/api/settings/check-defaults`. Every attribute maps to one key of the
response's `overrides` object, never the top-level effective values, so a null
attribute stays null and built-in timeouts never enter state (see
[check defaults: stored versus effective](../../docs/api/README.md#check-defaults-stored-versus-effective)).
Create and update PUT the whole document, with null for omitted attributes.
`retry_count = 0` is an explicit zero. `""`, `[]`, `{}` and empty timeout
entries are rejected, because the server stores them as null. Destroy is
`PUT {}`, which also removes the provisioned `Email` default channel. A server
without `overrides` in the response is reported as too old.

`resource_platform_regions.go` implements `ensafely_platform_regions` (PUT
replaces the selection, a set; an empty set sends `[]`) and the
`ensafely_platform_regions_available` data source (`GET
/api/platform-regions/available` plus the limit from `GET
/api/platform-regions`). Plan-limit (`QUOTA_EXCEEDED`), plan-ineligible and
unknown-region errors get their own diagnostics. Destroy calls
`DELETE /api/platform-regions` (#120), which restores the Plan's default
regions served by a Probe, capped at the Plan limit.

Tests: `resource_singletons_test.go` (mapping, validators, error text, reset
requests, data source) and the acceptance tests `TestAccCheckDefaults`,
`TestAccCheckDefaultsInheritedByChecks` (shared with T4: changing the defaults
plans no change to a Check that leaves inherited fields null),
`TestAccPlatformRegions` (including the Free plan's two-region limit and the
reset to the Free default `eu-paris`) and
`TestAccPlatformRegionsAvailableDataSource`. The shared acceptance Tenant is on
the unlimited seed plan, so both region tests bootstrap their own Free-plan
Tenant (`useFreeTenant`).

## HTTP client behavior

`internal/client` adds `Authorization: Bearer <key>` and JSON encoding. Path
segments built from user values go through `client.PathEscape`.

| Response | Retried? |
|---|---|
| 429 | Yes, every method (the limiter rejects before any handler runs). Waits `Retry-After` (seconds or HTTP date), else 1s doubling to 30s with jitter. A wait above 90s is not attempted. |
| 502/503/504, network error | GET/HEAD/OPTIONS/PUT/DELETE, or a request with `client.Idempotent()`. |
| Failed TCP dial | Yes, every method: nothing was sent. |
| 500 and other statuses | No. The API reports deterministic failures such as duplicates as 500. |

Five retries at most; the request context also bounds the total time.
Non-2xx responses are `*client.APIError` with `Quota` for `QUOTA_EXCEEDED`
(both server shapes), `Code` (`EMAIL_NOT_VERIFIED`), `RetryAfter` and the
`X-Request-ID`. Helpers: `IsNotFound`, `IsQuotaExceeded`, `IsConflict`,
`IsRateLimited`.

## Development and tests

```bash
go build ./packages/terraform-provider/...
go test ./packages/terraform-provider/...   # unit tests; acceptance tests skip without TF_ACC
./scripts/verify.sh tf                      # unit + acceptance against make e2e-up
```

`./scripts/verify.sh tf` runs [`scripts/tf-acceptance.sh`](../../scripts/tf-acceptance.sh):

1. `make -C packages/cloud e2e-up` (Docker: app and Postgres with
   `APP_ENV=test` and `ENABLE_TEST_ENDPOINTS=true`) in its own compose
   project, `tfacc-<worktree checksum>-<pid>`, on free `127.0.0.1` ports
   picked by Docker; the app URL is read with `docker compose port`;
2. `internal/acctest/cmd/acc-bootstrap` registers the Platform regions
   `eu-paris`, `us-washington` and `ap-singapore` (a platform probe token per
   region, created as the local platform admin), then signs up a fresh
   Tenant, verifies its email through `/api/test/emails`, and creates an
   `api_write` key. With `-plan paid2` (the harness default) it moves the
   Tenant to the unlimited seed plan, because the free plan allows one alert
   channel and the default Email channel takes it. The platform admin is
   `admin@test.com` from `ADMIN_EMAILS` in `packages/cloud/docker-compose.yml`,
   signed up on a fresh database. It refuses non-local endpoints;
3. builds the provider and runs `terraform init` and `terraform plan` of an
   empty configuration through a `dev_overrides` CLI config;
4. runs `TF_ACC=1 go test ./packages/terraform-provider/...` with
   `ENSAFELY_ENDPOINT`/`ENSAFELY_API_KEY` replaced by the local values;
5. `make e2e-down` (removes the volume and the project's image tag) on exit,
   failure, Ctrl-C or SIGTERM, unless the compose project was already running
   or `TF_ACC_KEEP_APP=1`. Stacks of killed runs of the same worktree are
   removed on the next start.

Prerequisites: Docker with compose, Terraform >= 1.11, Go, curl. Missing
prerequisites fail the run. Parallel runs, from one or several checkouts, do
not share or stop each other's stacks. `TF_ACC_COMPOSE_PROJECT`,
`TF_ACC_APP_PORT` and `TF_ACC_DB_PORT` pin the project and ports, e.g.
`TF_ACC_COMPOSE_PROJECT=cloud TF_ACC_APP_PORT=8090 TF_ACC_DB_PORT=5433` for
the shared stack of a plain `make e2e-up`.

Resource acceptance tests follow `TestAccWriteOnlyProbe`: create → empty plan
→ update → import → destroy, with `acctest.PreCheck` and
`tfversion.SkipBelow(tfversion.Version1_11_0)`. A new Tenant is on the free
plan; tests that need more must raise its plan through the local admin API.

The GitHub workflow `.github/workflows/terraform-provider.yml` runs the same
command on pull requests that touch this package, `docs/api/openapi.yaml` or
the harness, with Terraform 1.11 (the minimum).

## OpenTofu

OpenTofu supports write-only attributes since 1.11.0 (2025-12-09) with the
same semantics: always null in plan and state, displayed as
`(write-only attribute)`, and changes detected only through a companion
version attribute. The provider therefore needs OpenTofu >= 1.11.

`TestAccWriteOnlyProbe` passed against the acceptance app with OpenTofu
1.11.14 and 1.13.9 (and Terraform 1.11.4 and 1.17.0) on 2026-11-14. To run the
acceptance tests with OpenTofu, point terraform-plugin-testing at the binary
and give it an OpenTofu-valid provider address:

```bash
TF_ACC=1 TF_ACC_TERRAFORM_PATH="$(command -v tofu)" \
  TF_ACC_PROVIDER_HOST=registry.opentofu.org TF_ACC_PROVIDER_NAMESPACE=imcitius \
  go test ./packages/terraform-provider/internal/provider/ -run TestAcc
```

Without the two `TF_ACC_PROVIDER_*` variables OpenTofu rejects the default
test address (`registry.terraform.io/-/ensafely`). The CI job tests Terraform
only.

The release therefore targets the OpenTofu Registry as well as the Terraform
Registry; the submission steps are in the
[release checklist](../../docs/operations/tfprovider-release.md#owner-checklist).
