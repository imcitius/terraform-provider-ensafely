# ensafely_check_defaults (Resource)

Manages the Tenant's check defaults: the values an `ensafely_check` uses for
the settings it leaves null (interval, retries, timeouts, re-alert interval,
severity, alert channels and escalation policy). There is one per Tenant.

Every attribute is optional and maps to one stored override. An omitted (or
null) attribute is not overridden, so the built-in default applies and never
appears in state. Creating the resource replaces whatever defaults are stored
with this configuration; a change made in the settings editor shows up as
drift on the next plan.

Checks that leave a setting null follow these defaults without a diff on the
`ensafely_check`, so changing this resource never plans changes to Checks.

Requires Terraform 1.11+ (or OpenTofu 1.11+). Applying changes needs a Tenant
API key with the `api_write` scope; `api_read` is enough for `terraform plan`.

## Example usage

```terraform
# Tenant-wide defaults. Checks that leave these settings null inherit them.
resource "ensafely_check_defaults" "current" {
  check_interval    = "1m"
  retry_count       = 2
  retry_interval    = "10s"
  re_alert_interval = "1h"
  severity          = "warning"
  alert_channels    = ["Email"]

  # Only the listed check types are overridden; the others keep their
  # built-in timeout.
  timeouts = {
    http = "5s"
    dns  = "3s"
  }
}
```

## Schema

### Optional

- `alert_channels` (Set of String) Alert channel names Checks alert by default. Omit or set null for no default channels.
- `check_interval` (String) Check interval, for example `1m`. Omit or set null to use the built-in default.
- `escalation_policy` (String) Escalation policy name. Omit or set null to use the built-in default.
- `re_alert_interval` (String) Interval between repeated alerts while a check stays unhealthy, for example `1h`. Omit or set null to use the built-in default.
- `retry_count` (Number) Retries before a failure is reported. `0` is an explicit "no retries". Omit or set null to use the built-in default. (0)
- `retry_interval` (String) Wait between retries, for example `10s`. Omit or set null to use the built-in default.
- `severity` (String) Alert severity: `critical`, `warning` or `info`. Omit or set null to use the built-in default.
- `timeouts` (Map of String) Timeout per check type (`http`, `tcp`, `dns`, ...; `default` applies to types without an entry), for example `{ http = "5s" }`. Only the listed types are overridden; the others keep their built-in timeout. Omit or set null to use the built-in default.

### Read-Only

- `id` (String) Always `current`.

Empty values (`""`, `[]`, `{}`, an empty timeout) are rejected: omit the
attribute instead. The API stores them as "not overridden", so they would read
back as null.

## Destroy

Destroy resets **every** default to the built-in value (`PUT {}`); it does not
restore the values that were stored before Terraform managed the resource.

A new Tenant is provisioned with `alert_channels = ["Email"]`. Destroy removes
that too, so Checks without their own `alert_channels` stop alerting until
default channels are set again (in Terraform or in Settings → Check defaults).

## Import

```shell
terraform import ensafely_check_defaults.current current
```

The import ID is always `current`. Import reads the stored overrides; a fresh
Tenant imports with only `alert_channels = ["Email"]` set.
