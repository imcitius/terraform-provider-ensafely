# ensafely_connection (Resource)

Manages a Connection: a named, reusable set of host, port and credentials for
a PostgreSQL, MySQL, MongoDB or HTTP target. Checks reference it with
`connection_id`. Rotating the password here updates every Check that uses the
Connection.

The password and the HTTP headers are **write-only** arguments (Terraform
1.11 or newer, or OpenTofu 1.11 or newer). They are never stored in the plan
or state; the API never returns the password and returns header values masked
(`****`). Terraform cannot detect a change to a write-only value, so each one
is sent:

- on create, when it is set;
- on update, only when its version (`password_wo_version`,
  `headers_wo_version`) changes. If the value is null at that point, the
  stored password or headers are cleared.

Changing `password_wo` or `headers_wo` without changing its version produces
an empty plan and sends nothing; the API keeps the stored value.

## Example usage

```terraform
variable "orders_db_password" {
  type      = string
  sensitive = true
  # Ephemeral variables (Terraform 1.10+) can feed write-only arguments
  # without ever being stored.
  ephemeral = true
}

resource "ensafely_connection" "orders_db" {
  name     = "orders-db"
  type     = "postgres"
  host     = "db.example.com"
  port     = 5432
  username = "checker"

  # Write-only: never stored in plan or state. Bump the version to rotate.
  password_wo         = var.orders_db_password
  password_wo_version = 1

  params = {
    db_name  = "orders"
    ssl_mode = "require"
  }
}

resource "ensafely_connection" "status_api" {
  name = "status-api"
  type = "http"

  # Header values are secrets in the API (returned masked), so they are
  # write-only too. Bump the version to send a changed map.
  headers_wo         = { "X-Api-Key" = var.status_api_key }
  headers_wo_version = 1

  params = {
    base_url = "https://api.example.com/health"
  }
}

variable "status_api_key" {
  type      = string
  sensitive = true
  ephemeral = true
}
```

To rotate the password, change the value and increment
`password_wo_version` (for example from `1` to `2`) in the same apply. The
same applies to `headers_wo` and `headers_wo_version`; the whole map is sent
and replaces the stored headers.

For `http` Connections, a username with a password is sent as basic auth; a
password without a username is sent as `Authorization: Bearer <password>`.

## Schema

### Required

- `name` (String) Connection name, unique in the Tenant. Renaming updates the Connection in place.
- `type` (String) Protocol: `postgres`, `mysql`, `mongo` or `http`. Changing it updates the Connection in place.

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `headers_wo` (Map of String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) Extra request headers (`http`). Write-only, because the API treats header values as secrets and returns them masked. Requires `headers_wo_version`; the whole map is sent and replaces the stored headers.
- `headers_wo_version` (Number) Change this number to send `headers_wo` again. If `headers_wo` is null when the version changes, the stored headers are removed.
- `host` (String) Server host name or address. HTTP connections usually set `params.base_url` instead.
- `params` (Attributes) Protocol-specific settings. Keys set outside Terraform that this schema does not model are preserved on update. (see [below for nested schema](#nestedatt--params))
- `password_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) Password or token. Write-only: never stored in plan or state, and never returned by the API. Requires `password_wo_version`; changing only this value does not send it.
- `password_wo_version` (Number) Change this number to send `password_wo` again (rotate it). If `password_wo` is null when the version changes, the stored password is cleared.
- `port` (Number) Server port.
- `username` (String) User name. For `http`, a username with a password is sent as basic auth; a password without a username is sent as a Bearer token.

### Read-Only

- `id` (String) Server-assigned Connection ID (UUID). Use it as a Check's `connection_id`, and to import.

### Nested Schema for `params`

Optional:

- `auth_source` (String) Authentication database (`mongo`).
- `base_url` (String) Base URL used when a Check has no URL of its own (`http`). Must not contain a password: use `username` and `password_wo`.
- `db_name` (String) Database name (`postgres`, `mysql`, `mongo`).
- `replica_set` (String) Replica set name (`mongo`).
- `ssl_mode` (String) PostgreSQL `sslmode`, for example `require` (`postgres`).

Headers are not part of `params`: use `headers_wo`.

`params.base_url` must not contain a password (`https://user:pw@host`): the API
masks URL passwords, so they cannot be kept in state. A password-bearing
`base_url` set outside Terraform shows up masked in the plan and is removed on
apply.

The API accepts arbitrary keys in `params` (the app's JSON editor can set
them). Keys this schema does not model are not stored in state and are
preserved when Terraform updates the Connection.

## Destroy

Destroy deletes the Connection. The API refuses while Checks still reference
it; the error lists those Checks. When the Checks are in the same
configuration and reference `ensafely_connection.<name>.id`, Terraform already
destroys or updates them first.

## Import

```shell
terraform import ensafely_connection.orders_db 0b6f1f7e-4c4e-4f5b-9a63-2f4d3c2b1a00
```

Or use an import block (with `terraform plan -generate-config-out=generated.tf`
to generate configuration):

```terraform
import {
  to = ensafely_connection.orders_db
  id = "0b6f1f7e-4c4e-4f5b-9a63-2f4d3c2b1a00"
}
```

The ID is the Connection's UUID (`GET /api/connections` lists them). Import
reads every non-secret argument. The password, the headers and their versions
cannot be read back: after import, add `password_wo`/`password_wo_version`
(and `headers_wo`/`headers_wo_version` if used) to the configuration; the next
apply then sends them once. Until a version is set, the API keeps the stored
password and headers.
