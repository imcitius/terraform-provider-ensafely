# ensafely_alert_channel (Resource)

Manages an alert channel in the authenticated Tenant: where alerts of the
Checks that list the channel in `alert_channels` are sent. A channel has a
`name` and **exactly one** type block: `email`, `telegram`, `slack`,
`discord` or `webhook`.

- The name is the channel's identity. Changing `name` replaces the channel.
  Checks that reference it, for example
  `alert_channels = [ensafely_alert_channel.team.name]`, show their
  `alert_channels` change in the same plan and are updated in place.
  Deviation from #116: on rename, referencing Checks are updated in place (UUID and history kept), not replaced (Director decision 2026-11-15).
- Changing the type block replaces the channel. Other changes are in place.
- Every secret (bot tokens, signing secret, webhook URLs, the webhook HMAC
  secret and headers) is a write-only argument, see [Secrets](#secrets).

Requires Terraform 1.11+ (or OpenTofu 1.11+). Applying changes needs a Tenant
API key with the `api_write` scope; `api_read` is enough for `terraform plan`.

## Example usage

```terraform
resource "ensafely_alert_channel" "oncall_email" {
  name = "oncall-email"

  email {
    to = ["oncall@example.com", "sre@example.com"]
  }
}

resource "ensafely_alert_channel" "team_slack" {
  name = "team-slack"

  slack {
    default_channel = "C01ABCDEF"

    # Write-only: never stored in plan or state. Bump the version to rotate.
    bot_token_wo              = var.slack_bot_token
    bot_token_wo_version      = 1
    signing_secret_wo         = var.slack_signing_secret
    signing_secret_wo_version = 1
  }
}

resource "ensafely_alert_channel" "incident_hook" {
  name = "incident-hook"

  webhook {
    method       = "POST"
    content_type = "application/json"

    url_wo             = var.incident_hook_url
    url_wo_version     = 1
    secret_wo          = var.incident_hook_hmac
    secret_wo_version  = 1
    headers_wo         = { "X-Api-Key" = var.incident_hook_key }
    headers_wo_version = 1
  }
}

# Checks reference channels by name. Renaming a channel replaces it, and the
# referencing Check's alert_channels change appears in the same plan.
resource "ensafely_check" "api" {
  name           = "api"
  project        = "shop"
  alert_channels = [ensafely_alert_channel.team_slack.name]

  http {
    url = "https://api.example.com/health"
  }
}

# Ephemeral variables (Terraform 1.10+) can feed write-only arguments without
# ever being stored.
variable "slack_bot_token" {
  type      = string
  sensitive = true
  ephemeral = true
}

variable "slack_signing_secret" {
  type      = string
  sensitive = true
  ephemeral = true
}

variable "incident_hook_url" {
  type      = string
  sensitive = true
  ephemeral = true
}

variable "incident_hook_hmac" {
  type      = string
  sensitive = true
  ephemeral = true
}

variable "incident_hook_key" {
  type      = string
  sensitive = true
  ephemeral = true
}
```

The variables are declared with `ephemeral = true` (Terraform 1.10+) so the
values are never stored; see `examples/resources/ensafely_alert_channel`.

## Secrets

Each secret is a pair:

- `<field>_wo` (write-only, sensitive): never stored in plan or state. It is
  sent on create, and on update only when `<field>_wo_version` changes.
- `<field>_wo_version` (Number): a plain number you increase to send the
  current `<field>_wo` again, that is, to rotate it. It is required whenever
  `<field>_wo` is set.

Changing `<field>_wo` without changing its version is an empty plan and sends
nothing. To clear a stored secret, remove `<field>_wo` and change its version.
The API returns secrets masked (`****`), so changes made to them outside
Terraform are not detected, and `****` is rejected as a value. The webhook
`headers_wo` map is sent as a whole and replaces the stored headers.

## Behaviour

- Read and import use `GET /api/alert-channels/:name`. Refresh detects changes
  to non-secret settings and a type changed outside Terraform (which plans a
  replacement). A missing channel is removed from state and planned for
  creation again.
- Update sends the full non-secret configuration of the block (`PUT`).
  Settings this schema does not model, such as the legacy SMTP settings of old
  email channels, are kept.
- Channel types this provider does not manage (for example Teams, PagerDuty,
  Opsgenie, ntfy) cannot be read or imported; the error names the type.
- Destroy deletes the channel; an already-missing channel is treated as
  deleted. The default `Email` channel of every Tenant cannot be deleted: stop
  managing it with a `removed` block (`lifecycle { destroy = false }`) or
  `terraform state rm`.
- Create of a name that already exists fails with a hint to import it.

## Import

```shell
terraform import ensafely_alert_channel.team_slack 'team-slack'
```

Import reads the type block and its non-secret settings. Secrets and their
versions are not read back: set `<field>_wo` and `<field>_wo_version` in
configuration after import. The first apply then sends those secrets once,
because the version changes from unset.
